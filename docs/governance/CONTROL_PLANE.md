# 에이전트 통제 평면 (Agent Control Plane)

> **문제**: "모든 에이전트는 EG로만 컨트롤한다"는 원칙만으로는 부족하다.
> EG는 *무엇을 아는가(지식·정책·경험)* 를 담지만, *어떻게 행동하는가(역할·절차·경계)* 를 담기엔 결이 다르다.
>
> **해법**: EG 옆에 **문서 기반 통제 평면**을 둔다. 4개 계층 + 게이트.
> 사람은 이 5개의 손잡이만 돌리면 된다. 코드는 건드리지 않는다.

---

## 1. 한눈에

```
 ┌──────────────────────────────────────────────────────────────┐
 │  L1  COMPANY.md                    전사 · 헌법 · 아무도 못 넘음  │  경영진
 ├──────────────────────────────────────────────────────────────┤
 │  L2  AGENT_TEAM.md                 팀 · 협업 규칙 · 단계·검증   │  팀 리드
 ├──────────────────────────────────────────────────────────────┤
 │  L3  XXX_WORK.md                   업무 · SOP · 입출력·완료조건 │  업무 오너
 ├──────────────────────────────────────────────────────────────┤
 │  L4  SOUL.md                       개인 · 페르소나 · 어투·전문성 │  팀 리드
 ├──────────────────────────────────────────────────────────────┤
 │  ⛔ gate.yaml                       도구 allow/deny · 자율화·예산 │  보안(CCC)
 └──────────────────────────────────────────────────────────────┘
                              ▼ 컴파일
              에이전트 1개의 실효 시스템 프롬프트 + 정책 번들
                              ▼ 실행
       ① eg_search → ② skill_preview → ③ skill_run → ④ eg_record
                              ▼ 관제
                     OTel 스팬 → AOC (P3) → 이상 시 개입
```

**핵심 규칙 — 단조 축소(monotonic narrowing)**
하위 계층은 상위 계층을 **좁힐 수만 있고 넓힐 수 없다.**
L4 SOUL이 "이 도구도 써도 된다"고 써도, L1/L2/gate가 막았으면 막힌 것이다.
컴파일러(`dawn_core.control_plane`)가 이 불변식을 기계적으로 강제한다.

## 2. 각 계층은 무엇을 쓰는가

### L1 — `COMPANY.md` (루트 1개)
회사의 **비전·목표·전략·일하는 방식·절대 금지**.
전 에이전트에 무조건 주입된다. 여기 없는 금지는 전사 금지가 아니다.

- 쓸 것: 미션, 측정 가능한 목표(KPI), 전략, 공통 워커 루프, 행동 원칙, 절대 금지, 자율화 등급 정의
- 쓰지 말 것: 특정 팀·특정 업무 이야기 (→ L2/L3)

### L2 — `org/divisions/<본부>/<팀>/AGENT_TEAM.md`
**팀 단위 에이전트 전반의 행동양식.** 여러 에이전트가 한 팀으로 일할 때의 규칙.

- 쓸 것: 팀 미션, 역할 분담(리더/워커/검증자), 단계(phase)와 의존, 산출물 규격, 팀 특유의 금지·주의, 에스컬레이션 경로
- 참고: bastion 의 `BASTION.md` 가 이 계층의 선례다 (SOC 팀 하네스 전역 규칙)
- 쓰지 말 것: 개인 어투(→ L4), 특정 업무의 단계별 SOP(→ L3)

### L3 — `work/<도메인>/<업무>_WORK.md`
**구조화된 개별 단위 업무의 원리·원칙.** 재사용 가능한 SOP.

- 쓸 것: 트리거(언제 이 업무가 시작되나), 입력, 절차(단계별), 사용 도구, 위험도, 완료 조건(DoD), 실패 시 처리, 산출물 템플릿
- 하나의 `_WORK.md` = 하나의 재사용 가능한 업무. 여러 팀·여러 에이전트가 참조 가능.
- 쓰지 말 것: 누가 하는지 (→ 매니페스트가 연결한다)

### L4 — `org/agents/<에이전트-id>/SOUL.md`
**에이전트 개인의 페르소나 및 업무 지침.**

- 쓸 것: 나는 누구인가, 전문 영역, 판단 성향(보수적/공격적), 어투, 내가 특히 조심할 것, 내가 절대 안 하는 것
- 쓰지 말 것: 팀 규칙(→ L2), 절차(→ L3)

### ⛔ — `gate.yaml` (본부/팀/에이전트 어느 수준에나 둘 수 있음)
**기계가 강제하는 경계.** 문장이 아니라 목록이다.

```yaml
tools:
  allow: ["eg_search", "eg_record", "skill_preview", "read_file"]
  deny:  ["run_command", "docker_exec"]        # deny 가 allow 를 이긴다
autonomy: A1                                    # A0|A1|A2|A3
hitl:
  require_on: [destructive, irreversible, l3_data, cost_over_krw_100000]
budget:
  max_steps: 40                                 # 서킷 브레이커
  max_tokens: 200000
  max_tool_calls: 60
model:
  policy: from_eg                               # EG ModelPolicy 조회 (기본)
  force_local_when: [l3_data]                   # pol:l3-local-only
```

**병합 규칙**: 상위 → 하위 순으로 병합하되
`allow` 는 **교집합**, `deny` 는 **합집합**, 숫자 예산은 **최솟값**, 자율화 등급은 **더 낮은 쪽**.
→ 어느 하위 문서도 권한을 늘릴 수 없다.

## 3. 컴파일 — 5개 문서가 1개 에이전트가 되기까지

```bash
python -m dawn_core.control_plane compile ccc-soc-triage-01
```

컴파일러가 하는 일:

1. 에이전트 매니페스트(`org/agents/<id>/agent.yaml`)를 읽어 소속 팀·본부·담당 업무를 찾는다
2. `COMPANY.md` → `AGENT_TEAM.md` → 담당 `*_WORK.md` → `SOUL.md` 순으로 연결한다
3. 경로상의 모든 `gate.yaml` 을 §2 병합 규칙으로 합친다
4. **단조 축소 불변식을 검증한다** — 위반 시 컴파일 실패 (에이전트 기동 불가)
5. 실효 시스템 프롬프트 + 정책 번들(JSON)을 산출한다

산출된 번들은 P2 하네스가 그대로 먹고, P3 관제가 "이 에이전트는 이런 경계를 가졌어야 한다"의 기준선으로 쓴다.
런타임 행동이 번들과 어긋나면 그것이 **정합성 인시던트**다.

## 4. 검증 — Control Readiness Score

```bash
make control-lint
```

loop-engineering 의 *Loop Ready Score* 를 이 회사에 맞춘 것. 0–100점.

| 항목 | 배점 | 확인 |
|---|---|---|
| 문서 존재 | 25 | 모든 등록 에이전트가 L1~L4 4계층을 모두 갖췄나 |
| 경계 정의 | 25 | `gate.yaml` 의 tools/autonomy/budget 이 명시됐나 (기본값 의존 아님) |
| 거버넌스 | 20 | HITL 조건·에스컬레이션 경로·자율화 등급이 각 팀에 있나 |
| 루프 무결성 | 20 | 각 `*_WORK.md` 에 트리거·DoD·실패처리가 있나 |
| 관측성 | 10 | 텔레메트리 방출·관제 연동이 선언됐나 |

**80점 미만이면 CI 실패.** 통제되지 않는 에이전트는 배포하지 않는다.

## 5. 루프 엔지니어링 수용

에이전트는 대화가 아니라 **루프**로 산다. 루프의 5개 구성요소를 이 회사에 매핑:

| loop-engineering | 다노파기 구현 | 위치 |
|---|---|---|
| Automations/Scheduling | 이벤트 훅 + 큐 (상시 폴링 금지) | P2 `agents/runtime/` |
| Worktrees | 샌드박스 격리 실행 | P2 + P3 대응 플레이북 |
| Skills | bastion 33 Skill + `*_WORK.md` | L3 계층 |
| Plugins/Connectors | MCP (`experience_graph_mcp`) | P1/P2 |
| Sub-agents (maker/checker) | 검증자 ≠ 생산자 (L1 §6.2-2) | L2 팀 규칙 |
| Memory/State | **EG** — 대화 밖의 영속 척추 | P1 |
| Denylist/gate.yaml | `gate.yaml` | 이 문서 §2 |
| Circuit breaker | `budget.max_steps/tokens/tool_calls` | `gate.yaml` |
| Drift detection | 번들 vs 런타임 스팬 대조 = 정합성 인시던트 | P3 AOC |
| Autonomy L1–L3 | **A0–A3** (헌장 자율화 로드맵) | `gate.yaml` |

## 6. 하네스 엔지니어링 수용

harness = **미리 정의된 작업환경**. 대화를 잘 굴리는 대신, 일하기 전에
*누가(페르소나) · 무엇을(도구 경계) · 어떤 순서로(단계) · 어떻게 검증하며* 일할지를 세팅한다.

| harness-engineering | 다노파기 구현 |
|---|---|
| 전역 규칙 파일 (`BASTION.md`) | `COMPANY.md` (L1) + `AGENT_TEAM.md` (L2) |
| Agent 정의 md + frontmatter | `SOUL.md` (L4) + `agent.yaml` 매니페스트 |
| SKILL.md (도구 경계·조건 분기) | `*_WORK.md` (L3) + `gate.yaml` |
| 단계별 활성화 매트릭스 | `AGENT_TEAM.md` 의 phase/depends_on |
| 리더 무발화 (라우팅만) | 팀 오케스트레이터 규칙 (L2) |
| MAX_RETRIES / 안티패턴 | `gate.yaml budget` + AOC 이상탐지 |

el34 의 `bastion/src/harness/` 가 이 방법론의 SOC 버전 선례다. 우리는 그것을 **전사로 일반화**한다.

## 7. EG와의 관계 — 무엇을 어디에 두나

| | EG (P1) | 통제 평면 (이 문서) |
|---|---|---|
| 담는 것 | 지식·경험·정책·자산·조직 **그래프** | 역할·절차·경계 **문서** |
| 형태 | 노드/엣지, 질의 가능 | 마크다운 + YAML, 사람이 읽고 씀 |
| 갱신 주체 | 에이전트가 축적(`eg_record`) + 사람이 조정 | 사람이 작성 |
| 조회 시점 | 매 작업 시작 시 (`eg_search`) | 에이전트 기동 시 (컴파일) |
| 예 | "결제 자산은 L3·비가역" / "지난번 이 오류는 이렇게 풀었다" | "경리 에이전트는 이 5개 도구만 쓴다" |

**서로를 참조한다.** `gate.yaml` 의 `model.policy: from_eg` 처럼 통제 평면이 EG를 질의하고,
EG의 Persona 노드는 `SOUL.md` 를 가리킨다. 둘은 경쟁이 아니라 두 개의 손잡이다.

> 사람의 개입 = **EG 조정** + **통제 평면 문서 수정**. 코드 수정은 여전히 개입 수단이 아니다.

## 8. 실제로 어떻게 쓰나 (사람용 3분 가이드)

**"이 팀 에이전트가 너무 공격적이야"** → `AGENT_TEAM.md` 의 판단 성향 절을 고친다
**"이 에이전트만 조용히 시켜"** → 그 에이전트의 `SOUL.md` 를 고친다
**"이 업무 절차가 틀렸어"** → 해당 `*_WORK.md` 의 절차를 고친다
**"이 도구 못 쓰게 해"** → 가장 가까운 `gate.yaml` 의 `deny` 에 추가한다
**"전사 금지 하나 추가"** → `COMPANY.md` §6.3 에 추가한다
**"새 사업 시작"** → `org/businesses/<id>.yaml` 추가 → 본부/팀/에이전트 매니페스트 추가 → `make control-lint`

고친 뒤에는 항상:
```bash
make control-lint     # 80점 이상인지, 불변식 안 깨졌는지
make registry         # 레지스트리 정합성
```
