# 그룹웨어 사용법 — 3분 안내

**이 포털은 게시판이 아니라 관문이다.** 에이전트가 멈춰서 사람을 기다리는 곳,
그리고 사람이 에이전트 행동을 바꾸는 곳이다. 공지·문서·일정은 그다음이다.

관련: [`CONTROL_PLANE.md`](CONTROL_PLANE.md) (사전 통제) ·
[`AOC_OPERATIONS.md`](AOC_OPERATIONS.md) (사후 관제) · 이 문서 (사람의 개입 통로).

## 1. 권한 = 조직 × 능력

능력을 준다고 전사 권한이 생기지 않는다. **두 개를 곱한다.**

```
can(user, "hitl.approve")            이 사람이 승인 권한을 가졌나
can_approve(user, agent_org, sev)    ← 그 에이전트를 승인할 수 있나
```

승인자는 **그 에이전트의 조직이거나 상위 조직**이어야 한다. 경영관리부 사람이
CCC 에이전트의 방화벽 변경을 승인하면 그건 승인이 아니라 책임 회피다.

```
org:dawn ─┬─ org:mgmt ─┬─ org:ga    ← corp-admin-clerk-01 이 여기 소속
          │            ├─ org:hr
          │            └─ org:fin
          ├─ org:it ───── org:ccc   ← ccc-soc-triage-01
          ├─ org:aoc
          └─ org:ax
```

`org:ga` 요청은 `org:ga` · `org:mgmt` · `org:dawn` 사람이 승인할 수 있다.
`org:hr` 사람은 못 한다 — 형제 조직이다.

### 능력 목록

```bash
make portal-caps
```

| 능력 | 뜻 |
|---|---|
| `portal.view` | 열람 (기본) |
| `portal.post` | 공지·문서·일정 작성 |
| `hitl.view` | 승인 큐 열람 |
| `hitl.approve` | 승인/거부 — **자기 조직 트리 안에서만** |
| `hitl.approve.critical` | 최고 심각도(비가역·L3) 승인 |
| `eg.view` / `eg.edit` | EG 조회 / 조정 |
| `aoc.view` / `aoc.control` | 관제 열람 / 킬 스위치 |
| `admin` | 계정 관리 (다른 능력 전부 포함) |

```bash
dawn-web useradd hong --name 홍길동 --org org:ga --title "경리총무팀" \
  --capabilities "portal.view,portal.post,hitl.view,hitl.approve"
dawn-web usermod hong --capabilities "portal.view,hitl.view"   # 권한 변경
dawn-web usermod hong --disable                                # 사용 중지
```

## 2. 승인 큐 — 가장 먼저 보는 화면

에이전트가 비가역·고심각 행동 앞에서 **멈춰서** 여기로 올린다.
당신이 누르기 전에는 그 행동이 실행되지 않는다.

화면은 두 칸으로 갈린다:

```
내가 승인할 수 있는 것     ← 여기만 버튼이 있다
다른 조직 소관            ← 보이지만 누를 수 없다 (누가 눌러야 하는지는 보인다)
```

상세 화면에서 확인할 것:

| 보이는 것 | 왜 보는가 |
|---|---|
| **게이트가 올린 이유** | 왜 사람한테 왔나. 근거 없이 승인하지 마라 |
| **인자** | 실제로 무엇에 대해 실행되나 (금액·경로·대상) |
| **심각도** | 행동 비가역성 × 자산 등급. 6 = 최고 |
| **자산 / 정책** | 무엇을 건드리나, 어떤 규칙에 걸렸나 |
| **트레이스** | 그전에 무슨 일이 있었나 (`make aoc-replay T=<id>`) |

**확인 체크박스**를 눌러야 판정이 넘어간다. 비가역이면 문구가 바뀐다.
**사유는 감사 로그에 남는다** — 다음 사람이 읽는다.

> 한 번 판정된 요청은 **재판정할 수 없다.** 승인/거부 이력이 감사 증거다.

최고 심각도인데 버튼이 없다면 `hitl.approve.critical` 이 없는 것이다.
상위 조직 승인자에게 올려라 — 그게 정상 동작이다.

## 3. EG 조정 — 에이전트를 바꾸는 유일한 정식 경로

**코드를 고치지 않는다.** 페르소나(행동 원칙)와 정책(게이트가 평가하는 규칙)을
고치면 다음 작업부터 전 에이전트에 전파된다.

```
수정 → 스냅샷 → 검증(eg/validate.py) → 재주입 → 감사
        검증 실패 시 시드 자동 롤백. DB 는 손도 안 댄다.
```

고칠 수 있는 것은 둘뿐이다:

| | 무엇 | 바뀌는 것 |
|---|---|---|
| **페르소나** | 역할·어조·원칙·금지·에스컬레이션 규칙 | 에이전트 시스템 프롬프트 |
| **정책** | 진술·규칙식·심각도·집행 방식 | 행동 게이트의 판정 |

조직도·자산·존은 UI 로 안 고친다 — 그건 정책이 아니라 **인프라의 사실**이다.
시드 파일을 직접 고치고 리뷰를 받아라.

**변경 사유는 필수다.** EG 변경은 전 에이전트의 행동을 바꾼다. 왜 바꾸는지 없이
반영하지 않는다.

바꾼 뒤 확인:

```bash
make prompt A=corp-admin-clerk-01     # 시스템 프롬프트에 반영됐나
make eg-org O=org:ga                  # 조직 프로파일이 바뀌었나
```

되돌리려면 `/eg` 화면 하단의 변경 이력에서 스냅샷 경로를 확인하고
`var/groupware/eg-backups/` 에서 복원한다. 복원도 같은 검증을 탄다.

## 4. 관제

`aoc.view` 가 있으면 `/aoc` 에서 KPI·케이스·에이전트 상태를 본다.
상세는 **픽셀 오피스**(`:8800`)로 간다.

**킬 스위치는 포털에 원클릭 버튼을 두지 않았다.** 종료·격리는 되돌리기 어려운
행동이라 클릭 한 번이 너무 싸다. `aoc.control` 권한자가 CLI 로 한다:

```bash
dawn-aoc control pause <agent-id> --by human:<이름>
```

## 5. 문서 보안 등급

| 등급 | 뜻 | 누가 보나 |
|---|---|---|
| L0 | 공개 | 전원 |
| L1 | 사내 | 전원 |
| L2 | 제한 — 담당 조직 | `eg.edit` 또는 `aoc.view` 보유자 |
| L3 | 기밀 — 인사·재무·개인정보 | `org:hr` `org:fin` `org:ga` `org:mgmt` 또는 `admin` |

**등급을 초과한 문서는 제목도 안 나온다.** 목록에서 행 자체가 빠진다 —
"2026년 구조조정안" 같은 제목은 그 자체가 정보다.

자기가 못 읽는 등급으로는 문서를 만들 수 없다 (쓰고 나서 못 여는 문서가 생긴다).

## 6. 감사 로그

```bash
make portal-audit              # 최근 40건
make portal-audit A=hitl.      # 승인만
make portal-audit A=eg.        # EG 변경만
make portal-audit A=access.    # 접근 거부만
```

append-only 다. 지우는 API 를 만들지 않았다. 비밀번호·토큰은 자동 마스킹된다.

화면(`/audit`)에서는 관리자·EG 편집자·승인자만 전체를 보고, 나머지는
**자기 이력만** 본다.

## 7. 공개 홈페이지

미션·사업·조직을 `org/` 레지스트리에서 렌더한다. 사업을 추가하면
(`org/businesses/*.yaml`) 홈페이지에 자동으로 나타난다 — 별도 편집이 없다.

문의 폼은 허니팟 + 제출 속도 검사 + IP 레이트리밋 + 링크 개수 제한으로 막는다.
접수함은 `make inquiries`.

> **공개 프로세스는 사내 데이터에 손이 닿지 않는다.** EG·업무 DB·계정 저장소로
> 가는 임포트 경로 자체가 없고, 테스트가 그걸 고정한다.

## 8. 흔한 상황

| 상황 | 대처 |
|---|---|
| 승인 버튼이 안 보인다 | 조직 밖이거나 심각도가 높다. 화면에 이유가 쓰여 있다 |
| 에이전트가 계속 같은 걸 물어본다 | 승인 개입률이 높다 → 팀 `gate.yaml` 의 `hitl.require_on` 조정 |
| 에이전트가 자꾸 틀린다 | EG 조정 → 해당 페르소나의 원칙 보강, 또는 `work/*_WORK.md` SOP 보강 |
| EG 를 고쳤는데 안 바뀐다 | 화면에 "거부됨"이 떴는지 확인. 검증 실패면 롤백된 것이다 |
| 계정을 잠갔다 | `dawn-web usermod <계정> --enable` |
| 관리자 비밀번호를 잊었다 | `make portal-resetpw U=admin` — 임의 발급, 1회 출력 |
| 테스트를 돌렸더니 로그인이 안 된다 | 정상이다. 테스트·드릴은 매 실행 임의 비밀번호를 쓴다 (저장소에 자격증명을 두지 않기 위해). `make portal-resetpw` 로 다시 받아라 |

## 9. 배포 시 확인

```bash
DAWN_PORTAL_HTTPS=1        # HTTPS 뒤에 둘 때 — 세션 쿠키에 Secure 플래그
DAWN_PORTAL_SECRET=<32자+> # 여러 대로 확장할 때 세션 키 공유
DAWN_OFFICE_URL=...        # '관제' 화면이 여는 픽셀 오피스 주소
```

기본값은 `var/groupware/session.key`(0600)를 만들어 재사용한다.
`var/` 는 전부 gitignore 되고 계정 파일도 0600 이다.
