# P6 — 통합·검증·자사 운영 개시

## 목표
전 계층(EG·하네스·관제·업무시스템·그룹웨어)을 연결해 하나의 살아있는 회사로 가동한다. 오펜시브 레드팀으로 AOC를 검증하고, 자율화 A1 운영을 개시한다. 이 상태가 곧 외부 판매의 레퍼런스(테넌트 #0).

## 먼저 읽어라
- 전 참조 문서 (`docs/context/00~05`)
- P0~P5 완료 상태 (BUILD_LOG.md)

## 작업
1. **엔드투엔드 통합**: 사용자 요구 → 그룹웨어 → 팀 오케스트레이터 → 워커(EG 참조·게이트) → 업무 시스템 → 관제(수집·탐지·대응) → 픽셀오피스 표시 → (필요시) HITL → EG 축적. 이 전체 경로가 끊김 없이 도는지 확인.
2. **오펜시브 레드팀 (자사 검증)**: CCC 오펜시브 페르소나 에이전트로 자사 에이전트에 프롬프트 공격·jailbreak·인젝션을 시도(스코프: 자사 에이전트, zone:int 취약웹). AOC 탐지 커버리지를 측정. 놓친 공격은 탐지 룰·가드레일을 보강(→ EG/탐지 카탈로그 업데이트).
3. **자율화 A1 가동**: 각 조직 에이전트를 A1(에이전트 제안→원클릭 승인)로 운영 시작. 개입률·오탐율 KPI를 관제 대시보드에서 수집. 헌장의 승급 기준(A1→A2)에 도달하는지 관찰.
4. **인시던트 리허설**: 보안(유출 시도)·품질(할루시네이션)·정합성(목표 이탈) 각 1건을 유도해 탐지→트리아지→대응→리플레이 전 과정을 리허설. kill switch·자격증명 회수·롤백을 실제로 한 번씩 실행.
5. **멀티테넌트 준비 확인**: 자사=테넌트 #0 구조가 고객 테넌트 추가로 확장 가능한지 점검(EG 네임스페이스·데이터 격리·pol:no-cross-tenant). 실제 고객 온보딩 절차 초안을 문서화.
6. **운영 러너북**: 일상 운영·장애 대응·EG 조정 절차를 러너북으로 정리(사람 운영자용).

## 완료 조건 (DoD)
- [ ] E2E 경로가 끊김 없이 동작(요구→에이전트→업무→관제→표시→축적)
- [ ] 오펜시브 레드팀 실행, 탐지 커버리지 측정치 기록, 미탐 보강
- [ ] 자율화 A1 가동, KPI(개입률·오탐율) 수집 확인
- [ ] 인시던트 3종(보안·품질·정합성) 리허설 완료, 대응 액션 실제 실행
- [ ] kill switch·자격증명 회수·롤백 각 1회 실증
- [ ] 멀티테넌트 확장성 점검 + 고객 온보딩 절차 초안
- [ ] 운영 러너북 작성

## 자기검증
1. E2E 시나리오 1개(예: "신규 고객 문의 → 컨설팅 초안 → 승인 → 관제 확인")를 처음부터 끝까지 실행하고 전 구간 로그·스크린샷을 BUILD_LOG.md에.
2. 레드팀 리포트: 시도한 공격, 탐지된 것, 놓친 것, 보강 조치.
3. 인시던트 리허설 3종의 탐지→대응→리플레이 기록.
4. KPI 대시보드 스냅샷.

## 완료 후
- 자사 운영 데이터가 쌓이면 이것이 외부 판매의 살아있는 데모가 된다.
- 다음: AX 고객(대학→보안→마케팅) 온보딩. 고객 규정·조직·자산을 같은 EG 스키마로 채우는 작업 = P1의 고객 버전.
- 회사가 스스로를 운영하며 개선하는 루프(자율화 A2→A3 승급)를 지속.
