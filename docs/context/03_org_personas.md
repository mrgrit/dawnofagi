# 03. 조직·페르소나 (참조)

> 에이전트는 사람 조직도를 상속한다. 각 조직에 팀 에이전트(오케스트레이터) 1 + 워커 N. 페르소나는 EG 노드(02_eg_schema.md의 Persona)로 존재하며, 사람이 이를 수정해 개입한다.

## 4본부 조직
| 본부 | 부서/팀 | 미션 | 색(픽셀오피스) |
|---|---|---|---|
| **AOC본부** | 개발부·운영부·연구소 | 관제 서비스 개발 (자사 먼저 → 판매) | 청록 |
| **AX본부** | 대학·보안·마케팅 사업부 | AI 전환 사업 (자사 먼저 → 서비스) | 보라 |
| **IT운영본부** | 데이터센터운영·IT지원·CCC부·사업지원 | 인프라·보안, AOC 검증장 | 주황 |
| **경영관리부** | 인사·재무·경리총무·마케팅·영업·고객관리·비서 | 코퍼레이트, 자동화 1순위 | 파랑 |

## CCC부 (사이버보안 6팀)
SOC · CTI · 분석대응 · 오펜시브 · 보안운영 · 보안교육사업. 자사 관제 조직이자 **AOC본부의 방법론 검증장·첫 고객**. 오펜시브팀은 자사 에이전트에 레드팀(프롬프트 공격)을 돌려 AOC 탐지 커버리지를 검증한다. (초기 EG에는 org:ccc 단일 팀, 운영 안정화 후 6팀 분화)

| corporate | 경영관리 | 정형·반복 자동, 민감데이터 로컬, 금액임계·개인정보 시 HITL |

## 모델 배치 (04_tech_stack.md와 연동)
- R&D(AOC 개발·연구소) → Opus
- 컨설팅(AX) → Opus/Sonnet 혼합
- 관제·인프라(IT·CCC) → Sonnet + 로컬 gpt-oss
- 경영관리 정형 → Haiku / 로컬 open model (민감 인사·재무는 로컬 전용)

## 워커 루프 (모든 에이전트 공통)
1. `eg_search` — 작업 전 과거 경험·정책 참조
2. `skill_preview` — 실행 전 위험도 LOW/MED/HIGH 확인
3. `skill_run` — HIGH·destructive면 HITL 승인 게이트
4. `eg_record` — 완료 결과·finding 축적
