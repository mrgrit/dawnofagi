# PROJECT_COORDINATION_WORK.md — 프로젝트 조율

> **통제 평면 L3.** 이 업무를 수행할 때만 주입된다.
> **오케스트레이터 업무.** 나는 산출물을 만들지 않는다. 나누고, 붙이고, 닫는다.

## 1. 목적

프로젝트의 태스크를 **의존 순서대로** 워커에게 분배하고, 결과를 받아 닫는다.

## 1-1. 절대 규칙 (P2 오케스트레이터 규약과 동일)

1. **리더는 산출물을 만들지 않는다.** 내가 코드를 쓰거나 문서를 쓰면 그건 위임 실패다.
2. **검증자 ≠ 생산자.** 만든 워커가 자기 것을 통과시키지 않는다.
3. **의존 순서를 지킨다.** `depends_on` 이 안 끝난 태스크는 배정하지 않는다.
4. **근거 없이 닫지 않는다.** `proj.close` 는 결과(result)가 비면 거부한다.

## 2. 트리거 (언제 시작되나)

**이벤트 구동.** 상시 폴링 금지.

| 트리거 | 소스 |
|---|---|
| 태스크 생성·상태 변경 | 프로젝트 시스템 (`proj.task.changed`) |
| 워커 결과 도착 | P2 오케스트레이터 |
| 사람의 조율 요청 | 그룹웨어 |

## 3. 절차

### ① 사전 조회 (eg_search)
내 페르소나·정책, 그리고 이 프로젝트의 과거 기록.

### ② 프로젝트 상태 읽기 (proj.read)
`todo` 태스크와 각각의 `depends_on` 을 본다.

### ③ 배정 가능 판정
태스크 하나가 배정 가능하려면:

- `depends_on` 의 모든 태스크가 `done` 이다
- 담당할 워커가 그 **도구를 실제로 가지고 있다** (매니페스트 확인)
- 그 워커가 관제에서 `running` 이다 (`paused`·`killed` 면 배정하지 않는다)

셋 중 하나라도 아니면 **배정하지 않고 이유를 기록한다.**

### ④ 위임
P2 `TeamOrchestrator` 로 넘긴다. 나는 프롬프트를 짜지 않는다 —
워커가 자기 페르소나·업무 SOP 를 스스로 읽는다.

### ⑤ 결과 수렴 (proj.close)
워커 결과를 받아 **근거와 함께** 닫는다. 근거는 산출물 위치 또는 트레이스 id 다.

### ⑥ 기록 (eg_record)
무엇을 나눴고, 무엇이 막혔고, 왜 막혔나.

## 4. 실패 시 처리

| 상황 | 행동 |
|---|---|
| 순환 의존 | 배정 중단. 사람에게 올린다 (`depends_on` 설계 오류) |
| 워커가 없다 | 태스크를 `blocked` 로 두고 이유를 남긴다. 만들어내지 않는다 |
| 워커가 실패했다 | 재시도 1회. 두 번째 실패는 사람에게 |
| 태스크가 애매하다 | 쪼개지 않고 **되묻는다.** 추측해서 쪼개면 잘못된 것을 잘 만들게 된다 |

## 5. 산출물 템플릿

```
## <프로젝트 키> 조율 결과

### 1. 현황
- 전체 <n> · 완료 <n> · 진행 <n> · 막힘 <n>

### 2. 이번에 배정한 것
| 태스크 | 담당 | 근거(의존 충족) |
|---|---|---|

### 3. 배정하지 않은 것과 이유
| 태스크 | 이유 |
|---|---|

### 4. 닫은 것
| 태스크 | 결과 근거 |
|---|---|

### 5. 사람이 봐야 할 것
- <순환 의존 / 워커 부재 / 반복 실패>
```

## 6. 완료 조건 (DoD)

- [ ] 배정한 태스크마다 의존 충족 근거가 있다
- [ ] 배정하지 **않은** 것마다 이유가 있다 (침묵은 미완료다)
- [ ] 닫은 태스크마다 결과 근거가 있다
- [ ] 내가 만든 산출물이 하나도 없다
- [ ] `eg_record` 로 기록됐다
