# FEATURE_BUILD_WORK.md — 기능 구현

> **통제 평면 L3.** 코드를 만드는 업무의 표준 절차.

## 1. 목적

지시문(Pn)의 한 DoD 항목을 **검증된 코드**로 만든다.
"짰다"가 아니라 **"lint·test·control-lint 를 통과했고 실행 로그가 있다"** 가 완료다.

## 2. 트리거

| 트리거 | 소스 |
|---|---|
| Pn 지시문의 DoD 항목 착수 | `docs/instructions/` |
| 이슈·요구사항 등록 | 프로젝트 관리 시스템 (P5) |
| 인시던트 후속 보강 (탐지룰·가드레일) | AOC 케이스 종결 |
| 오케스트레이터의 위임 | 팀 오케스트레이터 |

## 3. 입력

`task_id`, `phase`(P0~P6), `dod_item`, `scope`(건드릴 영역), `constraints`

## 4. 절차

### 단계 1 — 참조 (`eg_search`)
```
질의: "이 기능 / 이 모듈 / 이 패턴에 대한 기존 구현·과거 결정·막혔던 것"
```
- **이미 있는지 먼저 본다.** 있으면 재사용·확장한다. 바퀴를 다시 만들지 않는다.
- 과거에 같은 벽에 부딪힌 기록(`Error`)이 있으면 그 `Recovery` 를 먼저 적용한다.
- 관련 `Policy` 를 조회해 제약을 확인한다 (테넌트 격리·L3·최소권한 등).

### 단계 2 — 설계
- 변경 범위(파일 목록)와 인터페이스를 먼저 정한다.
- **비가역 영향을 식별한다**: 스키마 변경 / 데이터 마이그레이션 / 외부 API 계약 / 배포.
  하나라도 있으면 → HITL.
- 테스트 계획을 함께 세운다. 테스트 없는 핵심 로직은 설계 미완이다.
- **하드코딩 검사**: 에이전트 행동 규칙을 코드 분기로 만들고 있지 않은가?
  `if team == "..."` / `if persona == "..."` 는 **결함이다.** EG·통제 평면 조회로 바꾼다.

### 단계 3 — 구현
- 작게. 기능 단위. 주변 코드의 주석 밀도·명명·관용구를 따른다.
- 시크릿을 넣지 않는다. 더미 값도 실제 키 패턴을 흉내내지 않는다.
- 새 외부 의존성이 필요하면 → **중단하고 단계 5**. 표준 라이브러리로 되면 그걸로 한다.

### 단계 4 — 검증
```bash
make lint && make test && make control-lint && make registry
```
- 실제 출력을 산출물에 붙인다. **실행하지 않은 것을 "된다"고 쓰지 않는다.**
- 검증 워커(구현자와 다른 에이전트)가 리뷰·반증한다.

### 단계 5 — 게이트 (해당 시 HITL)
| 조건 | 사유 |
|---|---|
| 새 외부 의존성 추가 | 공급망 위험 + 라이선스 |
| 배포 | 비가역 |
| 스키마 변경 / 데이터 마이그레이션 | 비가역 |
| 통제 평면·킬 스위치 관련 코드 | 자기 감시 계층 |
| 외부 API 계약 변경 | 하위 호환 |

### 단계 6 — 기록
- 커밋: `[Pn][DoD-x] 한 줄 요약`
- `BUILD_LOG.md` append: 무엇을·왜·검증 결과·새 의존성(이유·라이선스)·**남은 것**
- `eg_record`: 구현한 것, 왜 그렇게 했는지, **막혔던 것**
- 스펙이 모호했으면 `QUESTIONS.md`

## 5. 사용 도구

`eg_search`, `eg_record`, `skill_preview`, `skill_run`, `read_file`, `write_file`, `run_command`, `git_ops`, `run_tests`, `web_search`

## 6. 위험도 · 게이트

| 액션 | 위험도 | 게이트 |
|---|---|---|
| 읽기·설계·테스트 실행 | LOW | 없음 |
| 파일 작성·수정 | MED | 검증 워커 통과 |
| 의존성 추가 | HIGH | **HITL** |
| 배포·마이그레이션 | HIGH | **HITL** |
| 통제 평면 코드 수정 | — | **에이전트 금지** (사람 전용) |

## 7. 완료 조건 (DoD)

- [ ] `eg_search` 로 기존 구현·과거 결정을 조회했다
- [ ] 변경 범위와 비가역 영향을 식별했다
- [ ] 하드코딩된 에이전트 행동 규칙이 없다 (EG·통제 평면 조회로 구현)
- [ ] 핵심 로직에 테스트가 있다
- [ ] `make lint` 통과 — **실제 출력 첨부**
- [ ] `make test` 통과 — **실제 출력 첨부**
- [ ] `make control-lint` 80점 이상
- [ ] 시크릿이 없다 (gitleaks 통과)
- [ ] 검증 워커가 리뷰·반증했다
- [ ] 커밋 메시지에 `[Pn][DoD-x]`
- [ ] `BUILD_LOG.md` append (남은 것 포함)
- [ ] `eg_record` 완료

## 8. 실패 시 처리

| 실패 | 처리 |
|---|---|
| 테스트 실패 | **다음으로 넘어가지 않는다.** 원인을 BUILD_LOG 에 남기고 수정 |
| lint 실패 | 수정. lint 규칙 자체를 완화하지 않는다 (완화는 HITL) |
| control-lint 80점 미만 | 통제 문서를 채운다. 점수를 낮추지 않는다 |
| 스펙 모호 | **추측 금지.** `QUESTIONS.md` 에 남기고 의존하지 않는 부분만 진행 |
| 의존성 승인 거부 | 표준 라이브러리로 재구현하거나 범위 축소 |
| 서킷 브레이커 발동 | 중단 + 부분 산출물 커밋 + 남은 것 명시 |
| DoD 일부 미충족 | **숨기지 않는다.** 미충족 항목과 사유를 BUILD_LOG 에 명시 |

## 9. 산출물

```markdown
## [Pn][DoD-x] <제목>
### 무엇을 왜
### 변경 범위
- `path/to/file.py:12-40` — <무엇>
### 검증
```
$ make lint   → <실제 출력>
$ make test   → <실제 출력>
$ make control-lint → <점수>
```
### 새 의존성
<없음 | 패키지·버전·이유·라이선스>
### 남은 것
<없음 | 미충족 DoD 항목 + 사유>
```
