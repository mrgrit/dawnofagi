# CRM_INQUIRY_WORK.md — 고객 문의 처리

> **통제 평면 L3.** 이 업무를 수행할 때만 주입된다.
> **초안까지가 끝이다.** 발송·계약·금액 약속은 이 업무의 범위가 아니다.

## 1. 목적

홈페이지·메일로 들어온 고객 문의를 **분류**하고, 근거 있는 **응답 초안**을 만든다.

만들지 않는 것: 발송된 메일, 체결된 계약, 확정된 가격, 확정된 일정.
이 넷은 전부 사람이 누른다.

## 2. 트리거 (언제 시작되나)

**이벤트 구동.** 상시 폴링 금지.

| 트리거 | 소스 |
|---|---|
| 새 문의 접수 | 공개 홈페이지 문의 폼 (`crm.inquiry.new`) |
| 문의 재분류 요청 | 그룹웨어 |

## 3. 절차

### ① 사전 조회 (eg_search)
- 내 페르소나(`persona:corporate`)와 적용 정책을 읽는다.
- 같은 유형의 과거 문의 처리 기록을 찾는다. 있으면 그 결론을 근거로 쓴다.

### ② 문의 읽기 (crm.inquiry_read)
원문을 그대로 읽는다. **요약본으로 판단하지 않는다.**

### ③ 분류
다섯 중 하나로만 분류한다. 애매하면 `기타`로 두고 사람에게 올린다.

| 분류 | 뜻 | 다음 |
|---|---|---|
| `도입문의` | 제품·서비스 도입 검토 | 담당 영업 배정 요청 |
| `기술문의` | 기능·연동·규격 | 근거 문서 첨부해 초안 |
| `견적요청` | **금액이 걸린다** | 초안에 금액을 쓰지 않는다. 담당자 배정만 |
| `장애신고` | 운영 중 문제 | CCC 로 에스컬레이션 |
| `기타` | 위에 없음 | 사람 판단 |

### ④ 근거 수집 (doc.search / doc.read)
초안에 들어갈 **모든 사실 주장은 사내 문서에서 인용한다.**
문서에 없는 내용은 쓰지 않는다. 모르면 "확인 후 회신드리겠습니다"로 남긴다.

### ⑤ 초안 작성 (crm.inquiry_draft)
아래 템플릿을 따른다. **저장만 하고 보내지 않는다.**

### ⑥ 기록 (eg_record)
분류·근거·미확인 항목을 남긴다. 기록 없는 처리는 미완료다.

## 4. 절대 하지 않는 것

- **발송하지 않는다.** `comm.external_send` 는 비가역이고 사람 전용이다.
- **금액·할인·납기를 약속하지 않는다.** 견적요청은 담당자 배정까지가 끝이다.
- **계약을 만들지 않는다.** `crm.contract_sign` 은 실행부가 없다.
- **고객 개인정보를 초안 밖으로 옮기지 않는다.** 요약에도 이메일을 복사하지 않는다.

## 5. 산출물 템플릿

```
## 문의 #<id> 처리
**분류**: <5종 중 하나>   **상태**: 초안 (발송 전)

### 1. 확인된 사실
- <문의 원문에서 인용>
- <사내 문서 근거: 문서 #<id> "<제목>">

### 2. 응답 초안
<고객에게 보낼 본문. 존댓말. 확인된 것만 단정한다.>

### 3. 미확인 / 사람 확인 필요
- <모르는 것, 약속할 수 없는 것>

### 4. 다음 행동 제안
- <담당 배정 / 에스컬레이션 / 추가 조회>
```

## 6. 실패 시 처리 · 에스컬레이션

| 상황 | 어디로 |
|---|---|
| 견적·금액이 걸린다 | 영업팀 (사람) |
| 장애·보안 신고 | CCC부 |
| 문의에 개인정보가 과다하게 들어 있다 | 경영관리부 + 마스킹 후 보관 |
| 처음 보는 유형 | 사람. 추측하지 않는다 |

## 7. 완료 조건 (DoD)

- [ ] 분류가 5종 중 하나로 정해졌다
- [ ] 초안의 모든 사실 주장에 근거(문서 id 또는 원문 인용)가 붙었다
- [ ] 확인된 것과 미확인이 문장 단위로 갈렸다
- [ ] `eg_record` 로 기록됐다
- [ ] **발송되지 않았다**
