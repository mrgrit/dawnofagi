# EXPENSE_PROCESSING_WORK.md — 경비 처리

> **통제 평면 L3.** 이 업무를 수행할 때만 주입된다.
> **L3 데이터 업무** — 로컬 모델 전용, 금액 임계 HITL 필수.

## 1. 목적

제출된 경비 증빙을 분류·대조하여 **전표 초안**을 만든다.
지급 실행은 이 업무의 범위가 **아니다**. 초안까지가 끝이다.

## 2. 트리거

**이벤트 구동.** 상시 폴링 금지.

| 트리거 | 소스 |
|---|---|
| 경비 신청 제출 | 그룹웨어 경비 모듈 |
| 법인카드 명세 수신 | 카드사 연동 (월 1회) |
| 증빙 파일 업로드 | 문서관리 시스템 |
| 반려 건 재제출 | 그룹웨어 |

## 3. 입력

| 필드 | 필수 | 설명 |
|---|---|---|
| `request_id` | ✔ | 경비 신청 ID |
| `requester` | ✔ | 신청자 (사번 — 이름은 마스킹) |
| `amount_krw` | ✔ | 금액 |
| `evidence_ids` | ✔ | 증빙 문서 ID 리스트 |
| `claimed_category` | | 신청자가 적은 항목 (참고만, 신뢰하지 않음) |
| `occurred_at` | ✔ | 발생일 |

## 4. 절차

### 단계 1 — 참조 (`eg_search`)
```
질의: "거래처 <vendor> / 항목 <category> 의 과거 처리 전례"
```
- 같은 거래처·같은 유형의 과거 계정과목을 조회한다.
- **전례가 있으면 그것을 따른다.** 다르게 하려면 이유를 쓴다.
- 전례가 없으면 → **비정형**. 단계 5로 직행(자동 분류하지 않음).

### 단계 2 — 분류
- 계정과목 배정. **신청자가 적은 항목을 그대로 믿지 않는다.** 증빙으로 판단한다.
- 부서 배부 결정.
- 모호하면 추측하지 않고 단계 5.

### 단계 3 — 3자 대조
```
증빙 금액  ↔  신청 금액  ↔  예산/계약 잔액
```
- 셋이 일치하지 않으면 → 단계 5 + 불일치 내역 명시.
- **중복 지급 확인**: 동일 증빙 ID 또는 (거래처+금액+일자) 조합이 이미 처리됐는지.
  발견 시 → 단계 5 + **CCC부 동시 통보** (이상거래는 보안 인시던트일 수 있음).

### 단계 4 — 검증
- 다른 에이전트가 금액·계정과목·증빙 일치를 반증 시도한다.
- 검증자 ≠ 생산자. 내 초안을 내가 통과시키지 않는다.

### 단계 5 — 승인 큐 (HITL)
아래 중 **하나라도** 해당하면 사람 승인 없이 진행하지 않는다:

| 조건 | 사유 |
|---|---|
| 금액 > 100,000원 | 금액 임계 |
| L3 개인정보 포함 | 민감데이터 |
| 전례 없는 유형 | 비정형 |
| 3자 대조 불일치 | 정합성 |
| 중복 지급 의심 | 이상거래 |
| 예산 초과 | 통제 |

승인 요청에는 **판단 근거와 불확실한 점**을 함께 올린다. 사람이 3초 안에 판단할 수 있게.

### 단계 6 — 기록 (`eg_record`)
- 처리 전례 (거래처·항목·계정과목)
- **사람에게 올린 이유** — 어떤 유형이 자꾸 올라가는지가 자동화 확대의 근거다
- 원장 반영은 **append-only**. 정정이 필요하면 정정 분개를 추가한다

## 5. 사용 도구

`eg_search`, `eg_record`, `skill_preview`, `ledger_read`, `expense_read`, `expense_write`, `read_file`, `write_file`

**없는 도구(설계상 의도)**: `run_command`, `web_search`, `external_send`, `payment`
→ L3 데이터가 외부로 나갈 경로 자체를 차단한다.

## 6. 위험도 · 게이트

| 액션 | 위험도 | 게이트 |
|---|---|---|
| 조회·분류·대조 | LOW | 없음 |
| 전표 초안 작성 | MED | 검증자 통과 필요 |
| 원장 기입 | HIGH | **HITL 필수** |
| 지급 실행 | — | **이 업무의 범위 아님. 도구 없음** |

**모델**: `local_only` 강제 (`pol:l3-local-only`). 클라우드 모델 전송 시도 자체가 인시던트다.

## 7. 완료 조건 (DoD)

- [ ] `eg_search` 전례 조회를 실행했다
- [ ] 계정과목이 증빙 근거로 배정됐다 (신청자 주장 그대로가 아님)
- [ ] 3자 대조를 수행했고 결과가 기록됐다
- [ ] 중복 지급 확인을 수행했다
- [ ] 모든 금액에 증빙 문서 ID + 라인 참조가 붙었다. **출처 없는 숫자가 없다**
- [ ] 개인정보가 마스킹됐다 (`홍*동`, `1234-**-****`)
- [ ] 검증자가 반증을 시도했다
- [ ] HITL 조건 해당 시 승인 큐에 올렸고, 승인 전에 원장을 건드리지 않았다
- [ ] `eg_record` 완료 (전례 + 에스컬레이션 사유)

## 8. 실패 시 처리

| 실패 | 처리 |
|---|---|
| 증빙 판독 불가 | 반려 초안 + 사람 확인. 추측해서 금액을 쓰지 않는다 |
| 계정과목 모호 | 승인 큐로. 추측 분류 금지 |
| 3자 대조 불일치 | 승인 큐 + 불일치 상세. 자동 조정 금지 |
| 중복 의심 | 승인 큐 + CCC 통보. 자동 처리 금지 |
| 로컬 모델 사용 불가 | **작업 중단.** 클라우드로 대체하지 않는다 |
| 서킷 브레이커 발동 | 중단 + 현재 상태 저장 + 사람 통보 |
