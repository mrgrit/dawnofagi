# INCIDENT_INVESTIGATION_WORK.md — 인시던트 조사 (L2)

> **통제 평면 L3.** 트리아지(L1)가 `escalate` 한 건을 깊이 파는 업무.

## 1. 목적

**무슨 일이 일어났는지 사후 재구성 가능한 수준으로** 밝힌다 (EU AI Act 12조 정렬).
결론이 아니라 **타임라인과 증거 사슬**이 산출물이다.

## 2. 트리거

| 트리거 | 소스 |
|---|---|
| `alert-triage` 의 `escalate` 판정 | 트리아지 케이스 |
| 심각도 HIGH 이상 자동 승격 | AOC 트리아지 계층 |
| 품질 인시던트 (할루시네이션·작업 포기·요구 미달) | LLM-judge |
| 정합성 인시던트 (목표 이탈·기만 행동) | goal drift 탐지 |
| 사람의 조사 지시 | 그룹웨어 |

## 3. 입력

`case_id`, `triage_verdict`(트리아지 산출물 전문), `assets`, `time_window`, `incident_axis`(`security`|`quality`|`alignment`)

## 4. 절차

### 단계 1 — 참조 (`eg_search`)
과거 유사 인시던트, 알려진 `Error`→`Recovery` 사슬, 관련 `Playbook`.
**같은 인시던트를 두 번 처음부터 조사하지 않는다.**

### 단계 2 — 범위 확정
```
Asset → LOCATED_IN → Zone        어느 존까지 번졌나
Asset → CONNECTS_TO → Asset      옆으로 갈 수 있었나
```
- blast radius 를 EG 순회로 산정한다. 추측 금지.
- 크로스테넌트 영향 여부를 **반드시** 확인한다 (있으면 즉시 최고 심각도 + 사람 통보).

### 단계 3 — 타임라인 재구성
- 최초 발생 → 침투 경로 → 확산 → 탐지 → 현재. 각 항목에 **증거 1개 이상**.
- el34 존 경계 통과는 pipe 게이트(fw/ips) 이벤트로 확인된다. 통과 기록이 없으면 그 경로는 없었던 것이다.
- 에이전트 인시던트면 OTel 스팬 트리(`invoke_agent` → `chat`/`execute_tool`)로 재구성한다.

### 단계 4 — 근본 원인
| 축 | 원인 후보 |
|---|---|
| 보안 | 도구 오용 / 권한 남용 / 데이터 유출 / 프롬프트 인젝션 (OWASP Agentic, MITRE ATLAS 매핑) |
| 품질 | 할루시네이션 / 작업 포기 / 요구 미달 (MAST 실패모드 매핑) |
| 정합성 | 목표 이탈 / 기만 행동 / 통제 평면 우회 시도 |

**"원인 불명"도 유효한 결론이다.** 그럴듯한 원인을 지어내는 것보다 낫다. 단, 무엇을 확인했고 무엇을 못 했는지 쓴다.

### 단계 5 — 검증
검증자가 타임라인의 **각 인과 고리를 반증** 시도한다. 증거 없는 고리는 "추정"으로 강등된다.

### 단계 6 — 대응 권고
플레이북 중 필요한 것을 **권고**한다. 실행은 별도 HITL:
일시중지/kill · 자격증명 회수 · 도구 차단 · 샌드박스 격리 · 산출물 롤백 · 규제 보고

### 단계 7 — 기록 (`eg_record`)
`Experience` + `Error`/`Recovery` + 탐지 공백이 있었으면 **탐지룰 보강 제안**.

## 5. 사용 도구

`eg_search`, `eg_record`, `skill_preview`, `skill_run`, `siem_query`, `suricata_query`, `waf_query`, `docker_inspect`, `run_command`(읽기 명령만), `read_file`, `write_file`

## 6. 위험도 · 게이트

| 액션 | 위험도 | 게이트 |
|---|---|---|
| 로그·스팬 조회 | LOW | 없음 |
| `docker_inspect`, 읽기 명령 | MED | `skill_preview` 필수 |
| 상태 변경 명령 | HIGH | **금지** — 대응은 권고까지. 실행은 대응 담당 + HITL |
| 규제 보고 | — | 사람 전용 |

## 7. 완료 조건 (DoD)

- [ ] `eg_search` 로 과거 유사 건을 조회했다
- [ ] blast radius 를 EG 순회로 산정했다 (추측 아님)
- [ ] 크로스테넌트 영향 여부를 확인했다
- [ ] 타임라인의 **모든 항목에 증거**가 붙었다. 증거 없는 것은 "추정"으로 표시됐다
- [ ] 근본 원인이 3축 중 하나로 분류되고 표준 프레임워크(OWASP/ATLAS/MAST)에 매핑됐다
- [ ] 검증자가 인과 고리를 반증 시도했다
- [ ] 대응 권고가 플레이북 항목으로 명시됐다 (실행하지 않음)
- [ ] **리플레이 가능성 확인**: 이 산출물만으로 제3자가 사건을 재구성할 수 있는가
- [ ] `eg_record` + 탐지 공백 시 룰 보강 제안

## 8. 실패 시 처리

| 실패 | 처리 |
|---|---|
| 로그 유실로 타임라인 단절 | 단절 구간을 명시하고 "재구성 불가"로 남긴다. 메우지 않는다 |
| 근본 원인 미확정 | "원인 불명" + 확인한 것/못 한 것 목록 |
| 크로스테넌트 영향 발견 | 즉시 조사 중단 + 최고 심각도 + 사람 통보 (진행 전 승인) |
| 조사 중 진행 중 침해 확인 | 즉시 `respond_now` 경로 + HITL 동시 요청 |
| 서킷 브레이커 발동 | 중단 + 부분 타임라인 저장 + 사람 통보 |
