# P3 — AOC 관제 시스템·픽셀 오피스 시각화

## 목표
P2 에이전트들이 방출하는 텔레메트리를 수집·탐지·대응하는 관제 시스템을 만들고, 픽셀 오피스로 시각화한다. 자사 에이전트가 첫 관제 대상.

## 먼저 읽어라
- `docs/context/01_aoc_architecture.md` (5계층·이중탐지·대응·심각도·픽셀오피스)
- `docs/context/02_eg_schema.md` (심각도·게이트·섹터가 EG 순회로 나옴)
- `docs/context/04_tech_stack.md` (Assessor·OTel·el34 존)
- P2 에이전트 (관제 대상)

## 작업
### 관제 백엔드
1. **수집 계층**: P2의 OTel 스팬을 받아 공통 스키마로 정규화해 트레이스 레이크에 저장. el34 Assessor(`/assess`·`/activity`)를 확장/연동. PII 마스킹 내장.
2. **탐지·평가 계층 (이중)**:
   - 동기 가드레일: 입력(인젝션·유출)·행동(도구 화이트리스트·비가역 사전승인)·출력(민감정보) 게이트. P2 행동 게이트 엔진과 공유.
   - 비동기 평가: LLM-as-judge(할루시네이션·완료성·궤적) + 행위 이상탐지(스텝 폭주·토큰 급증·비정상 시퀀스). 판정 모델은 피감시 모델과 분리.
3. **트리아지·대응 계층**: 심각도 = Asset.irreversibility × SecurityLevel.rank (EG 순회). 대응 플레이북: 일시중지/kill·자격증명 회수·도구 차단·샌드박스 격리·산출물 롤백·HITL 에스컬레이션. kill switch는 별도 제어 계층.
4. **거버넌스·개선**: 에이전트 레지스트리(EG의 OrgUnit/Asset), KPI 대시보드(task success·HITL 개입률·가드레일 적중·할루시네이션율·MTTD/MTTR), 자율화 등급 관리.

### 픽셀 오피스 시각화 (apps/)
5. **섹터 = el34 존**: Asset→LOCATED_IN→Zone 순회로 방을 결정. pipe = 문(PEP). 존 색 = 민감도.
6. **3계층 뷰**: 빌딩(4본부=4층, 밝기=활동량) → 플로어(부서별 방) → 데스크(에이전트 실시간 ReAct·트레이스·EG 참조).
7. **아바타 인코딩**: 몸색=본부, 배지=모델, 모자=자율화등급, 이펙트=상태, **말풍선 대신 EG 아이콘(참조 중인 EG 노드)**. 클릭 시 그 에이전트로 드릴다운.
8. **텔레메트리 바인딩**: 모든 시각 요소가 실제 이벤트에 연결(아바타 위치=execute_tool 대상, 문 통과=IPS 이벤트, 이동 경로=자산 접근 시퀀스, 격리실 이송=대응 플레이북 발동). 장식 애니메이션 금지. 이벤트 발생 시에만 갱신.
9. **타임라인 스크러버**: 트레이스 리플레이로 인시던트 사후 재구성(EU AI Act 12조). 인시던트 리뷰 도구.

## 완료 조건 (DoD)
- [ ] 수집: P2 스팬이 정규화되어 저장, PII 마스킹 확인
- [ ] 동기 가드레일 3종 동작(입력·행동·출력)
- [ ] 비동기: LLM-judge 1종(할루시네이션 or 완료성) + 이상탐지 1종(스텝/토큰) 동작
- [ ] 심각도 자동 산정(EG 순회) + 대응 플레이북 1개 이상(예: kill+격리) 실행
- [ ] KPI 대시보드에 실측치 표시
- [ ] 픽셀오피스: 3계층 뷰, 아바타 인코딩, EG 아이콘, el34 존 매핑
- [ ] 시각 요소가 실제 텔레메트리에 바인딩됨(임의 데이터 아님)
- [ ] 타임라인 리플레이 동작

## 자기검증
1. P2 워커를 돌리고 → 픽셀오피스에서 해당 아바타가 올바른 존/방에 나타나는지 확인.
2. 비가역 작업을 유도 → 트리아지가 최고 심각도로 잡고, 대응 플레이북이 발동하고, 격리실 이송 애니메이션이 뜨는지 확인.
3. 할루시네이션 유도 케이스 → LLM-judge가 잡는지 확인.
4. 타임라인으로 위 인시던트를 리플레이 → 사후 재구성 가능 확인. 스크린샷/로그를 BUILD_LOG.md에.
