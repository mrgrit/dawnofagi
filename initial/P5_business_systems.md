# P5 — 업무용 시스템

## 목표
회사 운영에 필요한 업무 시스템(CRM·문서관리·프로젝트·경리 등)을 구축하되, **각 시스템의 업무를 에이전트가 수행**하도록 설계한다. 자사 업무 자동화가 곧 AX 데모.

## 먼저 읽어라
- `docs/context/03_org_personas.md` (어느 조직이 무슨 업무·자동화 대상)
- `docs/context/02_eg_schema.md` (업무 데이터도 Asset·SecurityLevel로 분류)
- `docs/context/05_conventions.md` (민감데이터 로컬·테넌트 격리·감사)
- P2 하네스 (업무 에이전트가 이 위에서 동작), P3 관제 (업무 에이전트도 관제 대상)

## 작업
우선순위(자동화 효과·저위험 순): 경영관리 정형 업무부터.
1. **문서·지식 관리**: 사내 문서 저장·검색. EG와 연동(문서→Asset). 컨설팅·개발 산출물의 근거 저장소.
2. **CRM / 고객관리**: 영업·고객관리팀 업무. 고객·계약·문의. corporate 페르소나 에이전트가 정형 처리, 금액·계약은 HITL.
3. **프로젝트·이슈 관리**: AOC/AX 사업 진행. 팀 오케스트레이터가 태스크를 워커에 분배하는 백엔드와 연동.
4. **경리·총무**: 경비·자산·정형 회계 처리. **민감(L3, 재무·급여)은 로컬 모델 전용 + HITL 필수**(pol:pii-hr-fin, pol:l3-local-only). 자동화하되 게이트 엄격.
5. **각 시스템 공통**:
   - 데이터를 EG의 Asset으로 등록(kind·irreversibility·SecurityLevel·Zone). 새 자산은 시드에 추가·검증.
   - 업무 에이전트는 P2 워커 루프로 동작(eg_search로 페르소나·정책 조회).
   - 모든 업무 행위는 P3 관제 대상(텔레메트리 방출).
   - 이벤트 구동(예: 새 문의 도착 → 에이전트 기동), 상시 폴링 아님.

## 완료 조건 (DoD)
- [ ] 문서·지식 관리 동작, EG 연동(문서=Asset)
- [ ] CRM 최소셋 동작, 정형 업무 1건을 에이전트가 자동 처리(HITL 경계 포함)
- [ ] 프로젝트·이슈 관리가 팀 오케스트레이터와 연동
- [ ] 경리·총무: L3 데이터가 로컬 모델로만 처리되고 HITL이 걸리는지 확인
- [ ] 모든 업무 시스템의 데이터가 EG Asset으로 분류·검증됨
- [ ] 업무 에이전트 행위가 P3 관제에 나타남(픽셀오피스에서 해당 방)

## 자기검증
1. 새 고객 문의 이벤트 → CRM 에이전트가 기동·정형 응답 초안 작성 → 관제 콘솔에 활동 표시 확인.
2. 경리 에이전트에 급여(L3) 관련 작업 지시 → 로컬 모델 사용 + HITL 게이트 확인.
3. 새 업무 자산을 EG 시드에 추가 → validate.py 통과 → 관제 섹터에 반영 확인. BUILD_LOG.md에.
