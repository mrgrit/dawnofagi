# 01. AOC 관제 아키텍처 (참조)

> AOC = Agent Operation Center. SOC 방법론을 에이전트에 응용한 중앙 관제 체계. 자사 에이전트가 첫 관제 대상.

## 5계층 참조 아키텍처
```
[런타임]  사용자 → 에이전트(계획·행동·관찰) → 도구·데이터
              │ 텔레메트리 (OTel GenAI 스팬)
              ▼
[1] 수집·정규화·저장   표준 스키마 · 트레이스 레이크 · PII 마스킹
[2] 탐지·평가          가드레일(동기) + LLM-judge(비동기) + 행위 이상탐지
[3] 관제·대응(콘솔)     트리아지 · 케이스 · 대응 플레이북   ──개입──┐
[4] 거버넌스·개선       레지스트리 · KPI · 레드팀 · 성숙도            │
              ▲──────────────────────────────────────────────────┘
              폐루프: 탐지→대응→런타임 개입(중단·격리·승인)
```

## 관제 대상 (인시던트 3축)
- **보안**: 도구 오용, 권한 남용, 데이터 유출 (OWASP Agentic T1–T15 / ASI01–10, MITRE ATLAS)
- **품질**: 할루시네이션, 작업 포기, 요구 미달 (MAST 실패모드, LLM-judge 평가)
- **정합성**: 목표 이탈, 기만 행동 (goal drift 탐지)

## 이중 탐지
- **동기 가드레일**: 실행 전/중 차단. 입력 게이트(인젝션·유출성 요구) · 행동 게이트(도구 화이트리스트, 비가역 행동 사전승인) · 출력 게이트(민감정보 차단).
- **비동기 평가**: 응답 후 스코어링. LLM-as-judge(할루시네이션·완료성·궤적) + 행위 이상탐지(스텝 폭주·토큰 급증·비정상 도구 시퀀스). 판정기는 피감시 모델과 분리(담합 방지).

## 심각도 = 비가역성 × 영향범위(blast radius)
- read < write < execute < irreversible. 비가역·광역은 최고 등급 + 사전 HITL.
- EG의 Asset.irreversibility × SecurityLevel.rank로 자동 산정 (02_eg_schema.md 참조).

## 대응 플레이북
일시중지/kill · 자격증명 회수 · 도구 차단 · 샌드박스 격리 · 산출물 롤백 · HITL 에스컬레이션 · 규제 보고. Kill switch는 별도 제어 계층(에이전트가 수정 불가), stop≠de-authorize.

## el34 바인딩 (실물 앵커)
섹터는 가상 존이 아니라 el34 실제 세그먼트에 바인딩. pipe 존의 fw/ips = "존 사이의 문" = 정책 집행 지점(PEP). 그 통과가 Suricata/ModSec 이벤트로 실제 기록됨. Assessor 레이어(/assess·/activity) = 수집 계층의 원형.

## 관제 주체 = 에이전트 (SOC와의 차이)
L1 트리아지 에이전트 / L2 조사 에이전트 / 인간 게이트(비가역·고심각·신규 유형만). human-on-the-loop. 개입률은 낮을수록 성숙.

## 시각화 = 픽셀 오피스 (P3에서 구축)
공간=자산 지형, 에이전트=방문자. 3계층 뷰(빌딩/플로어/데스크). 아바타: 몸색=본부, 배지=모델, 모자=자율화등급, 말풍선 대신 EG 아이콘(참조 중인 EG 노드 노출→개입 지점 식별). 모든 픽셀이 텔레메트리에 바인딩.
