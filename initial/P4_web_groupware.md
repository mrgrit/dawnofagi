# P4 — 홈페이지·그룹웨어

## 목표
회사 공개 홈페이지와 사내 그룹웨어(포털)를 구축한다. 그룹웨어는 사람이 EG를 조정하고 HITL 승인을 처리하는 관문이기도 하다.

## 먼저 읽어라
- `docs/context/00_charter.md` (회사 소개 콘텐츠)
- `docs/context/03_org_personas.md` (조직 구조 — 그룹웨어 권한)
- `docs/context/04_tech_stack.md` (배포 위치·인증)
- `docs/context/05_conventions.md` (인증·최소권한·테넌트 격리)

## 작업
### 공개 홈페이지 (apps/website)
1. **콘텐츠**: 회사 미션("AI 역사가 AGI로 가는 길에 필요한 것들을 만들어 공급하고 확산한다"), 두 사업(AOC·AX), 조직 소개. 헌장 기반.
2. **배포**: el34 dmz 앞단(공개). 정적/SSR 선택은 CC 재량.
3. **보안**: 공개 자산이므로 L0. 폼(문의)은 입력 검증·스팸 방지.

### 사내 그룹웨어 (apps/groupware)
4. **인증·권한**: 조직(EG OrgUnit) 기반 권한. 최소권한. el34 user/int 존에 배치.
5. **핵심 기능(최소셋)**: 공지·문서·일정·구성원 디렉터리. 조직도는 EG의 OrgUnit에서 렌더.
6. **HITL 승인 관문**: P2/P3의 행동 게이트가 만든 승인 대기 큐를 사람이 처리하는 UI. 승인/거부/에스컬레이션. **이것이 사람이 에이전트에 개입하는 주 통로 중 하나.**
7. **EG 조정 UI (핵심)**: 사람이 Persona/Policy를 조회·수정하는 화면. 수정 시 validate.py 검증 → 재주입 → eg_search 반영. "사람은 EG를 조정함으로써 개입한다"의 실물. (편집은 권한자만, 변경 이력 감사)
8. **AOC 콘솔 연동**: P3 관제 콘솔·픽셀오피스를 그룹웨어에서 접근(권한별).

## 완료 조건 (DoD)
- [ ] 공개 홈페이지 배포, 미션·사업·조직 표시
- [ ] 그룹웨어 인증·조직 기반 권한 동작
- [ ] 공지·문서·일정·디렉터리 최소셋 동작
- [ ] HITL 승인 큐 UI에서 실제 승인/거부가 P2/P3 게이트에 반영
- [ ] EG 조정 UI에서 Persona 1건 수정 → 검증 → 반영 → 감사 이력 확인
- [ ] AOC 콘솔·픽셀오피스가 그룹웨어에서 권한별 접근

## 자기검증
1. 권한 없는 계정으로 EG 조정·AOC 콘솔 접근 시도 → 차단 확인.
2. P2 워커가 비가역 작업으로 HITL 큐에 항목 생성 → 그룹웨어에서 승인 → 워커가 진행하는지 확인.
3. EG 조정 UI로 Persona principles 수정 → 해당 조직 워커 행동 변화 확인 → 이력 기록. BUILD_LOG.md에.
