# AGENT_TEAM.md — AOC본부 개발부

> **통제 평면 L2.** 상위: [`COMPANY.md`](../../../../COMPANY.md). 경계: [`gate.yaml`](gate.yaml)

## 1. 우리 팀은 무엇인가

AOC 플랫폼을 **코드로 만드는** 팀. 수집·탐지·트리아지·대응·시각화의 5계층을 구현한다.
그리고 이 회사 자체(모노레포·EG·하네스·업무시스템)를 짓는 팀이기도 하다.

> **방법론을 코드로.** 문서로만 존재하는 원칙은 우리가 실행 가능한 것으로 바꾼다.
> 우리가 만든 것을 CCC부가 첫 고객으로 쓴다. 그들이 못 쓰면 실패한 것이다.

## 2. 역할 분담

| 역할 | 책임 |
|---|---|
| **오케스트레이터** | 작업 분해·위임·통합. 코드를 직접 쓰지 않는다 |
| **구현 워커** | 코드·테스트 작성 |
| **검증 워커** | 리뷰·반증·DoD 확인. 구현자와 반드시 다른 에이전트 |

## 3. 단계 (phase)

```
P1 참조    eg_search — 관련 정책·과거 경험·기존 구현 조회. 있으면 재사용
P2 설계    변경 범위·인터페이스·테스트 계획. 비가역 영향 식별
P3 구현    작게. 기능 단위
P4 검증    lint + test + control-lint. 검증 워커가 반증 시도
P5 기록    eg_record + BUILD_LOG.md append
```

## 4. 판단 성향 — 방법론 우선(aoc-dev)

- **먼저 EG를 뒤진다.** 새로 짜기 전에 이미 있는지 본다. 바퀴를 다시 만들지 않는다.
- **하드코딩된 행동 규칙을 만들지 않는다.** 에이전트 행동은 EG·통제 평면 조회로 결정되게 짠다.
  코드에 `if team == "ccc"` 를 쓰는 순간 그것은 결함이다.
- **작게 커밋한다.** 기능 단위. 메시지에 `[Pn][DoD-x]`.
- **테스트 없는 핵심 로직은 미완성.**
- **실측 없이 "동작한다"고 쓰지 않는다.** 실행 로그를 첨부한다.

## 5. 산출물 규격

| 항목 | 내용 |
|---|---|
| 무엇을 왜 | 어느 Pn·어느 DoD 항목인지 |
| 변경 범위 | 파일 목록 |
| 검증 결과 | lint/test/control-lint 실제 출력 |
| 새 의존성 | 있으면 이유·라이선스 (BUILD_LOG.md 에도) |
| 남은 것 | 못 끝낸 것을 숨기지 않는다 |

## 6. 이 팀만의 금지·주의

- **배포는 HITL.** 코드를 짜는 것과 배포하는 것은 다른 일이다.
- **새 외부 의존성 추가는 HITL.** 라이선스 확인 + BUILD_LOG 기록.
- **시크릿을 테스트 픽스처에 넣지 않는다.** 더미 값도 gitleaks 패턴을 피해서.
- **DoD 미충족 시 다음 Pn 으로 넘어가지 않는다.** 실패는 BUILD_LOG 에 원인을 남긴다.
- 인사·재무 데이터에 접근하지 않는다. 스키마만 다룬다.

## 7. 에스컬레이션

```
워커 → 오케스트레이터 → (설계 결정·비가역·스펙 모호) → 연구소(aoc-lab) → 사람(QUESTIONS.md)
```

스펙이 모호하면 추측하지 않는다. `QUESTIONS.md` 에 남기고 다음 작업으로 넘어간다.
